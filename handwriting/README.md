# Noto · сбор почерка — веб-версия

Статический сайт для сбора рукописных образцов: те же общие ядра заданий, что
и в iOS-приложении (русское — 758 строк, английское — 871), тот же порядок
выдачи, та же схема данных (`noto-0.1`) и тот же серверный эндпоинт. Ни сборки,
ни зависимостей — обычные файлы, которые можно положить на любой статический
хостинг. Интерфейс — на русском и английском (переключатель RU/EN в шапке
каждого экрана), сбор — только для взрослых (18+), см. «Языки, английское
ядро, 18+ и счётчик сообщества» ниже.

Работает на iPad (Apple Pencil), Android-планшетах (S Pen), телефонах и в
десктопных браузерах.

Кроме слов, приложение собирает рукописные **математические символы** и умеет
переписать решение задачи почерком писателя — см. «Формулы почерком» ниже.

## Что уже проверено

* Сквозной прогон в Chrome: создание писателя → согласие → задание → письмо
  пером → сохранение → пропуск → возврат → экспорт → импорт.
* IndexedDB (включая составной индекс очереди), черновики, восстановление
  курсора при импорте.
* Сетевой путь до Edge Function из браузера: CORS-предзапрос проходит, `apikey`
  принимается, функция отвечает.
* Символы и «Решение почерком» в Chromium (Playwright): согласие 0.1 → 0.2
  перед символами, письмо символов с образцом на листе, пропуск, черновик и
  возврат после перезагрузки, раздельные курсоры слов и символов, дописывание
  недостающих символов из решения и возврат к нему, экспорт PNG/SVG/JSON,
  печать, экспорт → импорт с символами, ни одной ошибки в консоли.
* Порядок заданий совпадает по правилам с iOS: 751 задание из 759 строк
  (повторы, у которых оригинал слишком близко к концу, отбрасываются — так же,
  как в Swift), ярусы монотонны, минимальный разрыв повтора ≥ 75, порядок
  детерминирован по `writer_id`.

## Где это живёт и как попадает в прод

Прод — **https://pencora.app/handwriting/**, и это GitHub Pages, а не
Cloudflare: сайт публикуется из **отдельного публичного репозитория**
`gleb31415/handynotes-site` (в нём лежит содержимое `Noto2/web/` в корне, плюс
`CNAME`). Этот репозиторий приватный, а Pages не публикует приватные репо на
бесплатном плане — отсюда и разделение.

`Noto2/web/handwriting/` здесь — **источник правды**; в сайтовом репозитории
лежит его копия. После изменений выкатка — обычное копирование:

```bash
git -C /path/to/handynotes-site pull
rsync -a --delete Noto2/web/handwriting/ /path/to/handynotes-site/handwriting/
git -C /path/to/handynotes-site add handwriting && \
git -C /path/to/handynotes-site commit -m "..." && \
git -C /path/to/handynotes-site push
```

Pages пересобирается сам, обычно за полминуты. Все пути внутри приложения
относительные, поэтому подпапка ничего не ломает.

Ссылки с сайта на него нет и не должно быть: это внутренний инструмент сбора,
он закрыт `Disallow` в `robots.txt` и `noindex` в своём `<head>`, и раздаётся
ссылкой тем, кто пишет.

Файлы под `Noto2/web/` попадают в область автосинхронизации Xcode — каждый из
них **поимённо** перечислен в `membershipExceptions` в `project.pbxproj`.
Добавляешь сюда файл — добавь его и туда, иначе он уедет в бандл приложения.

## Локальный запуск

ES-модули не работают через `file://`, нужен любой http-сервер:

```bash
cd Noto2/web/handwriting
python3 -m http.server 8777              # только этот компьютер
python3 -m http.server 8777 --bind 0.0.0.0   # чтобы зайти с планшета по Wi-Fi
```

Затем `http://<ip-компьютера>:8777/`. По http:// не будет Service Worker
(офлайн-кеша приложения) и Wake Lock — сами данные и IndexedDB работают.

## Запасной хостинг: GitHub Pages

`.github/workflows/handwriting-pages.yml` публикует **только** эту папку в корень
`https://<owner>.github.io/<repo>/`. Нужно один раз включить Settings → Pages →
Source = GitHub Actions; для приватного репозитория Pages работает только на
платном плане.

### Ничего не теряется при перезагрузке

* Образец пишется в IndexedDB **до** любой попытки отправки.
* Недописанное слово чекпоинтится через 0.4 с после каждого штриха и при уходе
  страницы в фон — вкладка, выгруженная iOS, вернётся к тому же слову с теми же
  штрихами.
* Курсор, ответы на вопросы и согласие живут на писателе, а не на устройстве.
* Порядок заданий детерминирован: перезагрузка не может перетасовать хвост
  под уже сохранённым курсором.

### Несколько писателей

Устройство передаётся из рук в руки, поэтому в приложении список писателей, а не
одна личность. У каждого — свой `writer_id` (UUID), своё согласие, свой прогресс
и свои ответы на вопросы о почерке. Ничего чужого не перезаписывается;
удаление писателя удаляет только его образцы.

Вопросы о почерке (`can_write_cursive`, `habitual_script`) задаются один раз,
после 12-го задания, и едут в конверте каждой последующей отправки.

### Отправка

`POST <project>/functions/v1/samples`, конверт совпадает с iOS-клиентом:

```json
{ "writer_id": "...", "consent_text_version": "0.3", "capture_from_notes": false,
  "can_write_cursive": "fluent", "input_device": "stylus", "habitual_script": "combined",
  "task_language": "ru",
  "samples": [ /* образцы noto-0.1 */ ] }
```

Батчи по 25 образцов и не больше ~1.2 МБ: один большой upsert не укладывается в
восьмисекундный таймаут Postgres, отменяется, и очередь встаёт навсегда.
Отправка идемпотентна (upsert по `sample_id`), поэтому «Отправить всё заново»
не создаёт дублей. Отправку можно выключить в настройках — тогда данные
остаются на устройстве и выгружаются в JSON.

### Формат образца

Тот же, что у iOS. Точка — `[x, y, t, p, altitude, azimuth]`: координаты в
единицах `canvas_w`/`canvas_h` (Y вниз), `t` — мс от первой точки образца,
`p` — сырое давление 0..1 (0, если устройство его не сообщает), углы — в
радианах (0 для пальца и мыши). Границы штрихов — только физические отрывы
пера. Поля задания (`task_index`, `word_group`, `order`, `prompt_id`) те же, что
в общем ядре, поэтому образцы из браузера и с iPad сравнимы напрямую.
`app_version` у веб-образцов — `web-…` (`web-1.0.0` до появления символов,
`web-1.1.0` с ними), по нему их видно в датасете.

Семантика захвата повторяет `HandwritingPromptCanvas.swift` намеренно:

| Что | iOS | Веб |
| --- | --- | --- |
| частота | `event.coalescedTouches(for:)` — полная частота устройства | `getCoalescedEvents()`, с откатом на само событие, если браузер их не отдаёт |
| точки на отрыве | пишутся (`touchesEnded` тоже коалесцированный) | пишутся |
| система координат | замораживается на первой точке слова, ресайз меняет только отрисовку | так же |
| `t` | `Int((touch.timestamp − t0) × 1000)` | `Math.round(event.timeStamp − t0)` |
| давление | `touch.force / maximumPossibleForce` | `event.pressure` |
| углы | только для `.pencil`, иначе 0 | только для `pointerType === 'pen'`, иначе 0 |
| `dpr` | `traitCollection.displayScale` | `window.devicePixelRatio` |

Три сознательных отличия:

1. **Округление.** iOS пишет полные `Double`; здесь `x`/`y` округляются до
   0.01 px, давление до 0.001, углы до 0.0001 — это ниже разрешения любого
   стилуса, но payload меньше почти вдвое.
2. **Давление пальца.** На iOS палец без 3D Touch даёт 0; в вебе спецификация
   предписывает 0.5 для устройств без датчика. Собирать всё равно нужно пером.
3. **Частота зависит от браузера.** Она не обещается, а **измеряется**: под
   листом показывается «N точек · M Гц» для текущего слова. Если браузер не
   поддерживает `getCoalescedEvents`, там будет частота кадров (60–120 Гц)
   вместо 240 Гц у Pencil в родном приложении.

### Экспорт и импорт

Экспортированный файл — **буквально конверт загрузки**, его можно отправить на
сервер одной командой:

```bash
curl -X POST "$PROJECT/functions/v1/samples" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' --data @noto-писатель-1a2b3c4d.json
```

«Экспорт всех» кладёт конверты в поле `writers`. Импорт принимает оба вида,
не трогает уже существующие `sample_id` и подтягивает курсоры писателя:
курсор слов — до максимального `order` среди слов (`prompted_word` или
образцов без `sample_type`), курсор символов — до максимального `order` среди
символов (`prompted_glyph`, кроме дописанных вне очереди). У слов и символов
нумерация `order` своя, поэтому смешивать их нельзя.

## Языки, английское ядро, 18+ и счётчик сообщества

**Язык интерфейса.** `js/i18n.js`: `?lang=ru|en` в адресе (ссылка из
приложения) → запоминается в `localStorage` `hn-lang` (тот же ключ, что у
основного сайта) и убирается из адреса, чтобы перезагрузка не отменяла
переключение; без параметра — сохранённый выбор, затем язык браузера (`ru…` —
русский, иначе английский). Статический текст размечен `data-i18n`,
`data-i18n-html`, `data-i18n-attr`; переключатель RU/EN в шапке каждого экрана
перерисовывает всё на лету (`langchange`). Модули компоновщика (`compose.js`,
`mathlayout.js`, `solution.js`, `textink.js`, `glyphs.js`, `tasks.js`,
`util.js`) скопированы и в бандл FormulaLab приложения, поэтому i18n.js не
импортируют: их русские сообщения переводятся там, где показываются
(`translateEngineMessage`). Названия символов в `math_glyphs.json` есть только
по-русски — в английском интерфейсе показываются сам символ или его LaTeX и
английское название категории.

**Английское ядро.** Язык сбора — отдельный от языка интерфейса выбор на всю
страницу («Русские слова / Английские слова» над списком писателей и над
листом; по умолчанию — `?lang=`, затем язык интерфейса; хранится в `meta`
`collect_lang`). У писателя — `task_language` (едет в конверте), у каждого
языка свой курсор и свой черновик. Английское ядро начинается с 18 опорных
слов (`anchor`) — они идут первыми, в порядке файла, без перемешивания и не
трогают генератор, поэтому у русского ядра (опорных слов нет) порядок выдачи
прежний.

**18+ и согласие 0.3.** На экране согласия два обязательных флажка: согласие и
«Мне уже исполнилось 18 лет» (`consent.adult = true`). Писатель, согласившийся
раньше (0.1/0.2, без `adult`), видит согласие ещё раз с пометкой «подтвердите
возраст», прежде чем писать, открывать символы или «Решение почерком»;
его образцы ждут в очереди — `SyncEngine` не отправляет ничего писателю без
согласия 0.3 и `adult` (`consentAllowsUpload`). 0.3 покрывает всё, что
покрывало 0.2, так что логика символов прежняя.

**Счётчик сообщества.** Над списком (и строкой над листом): «N человек уже
пишут · следующая модель — при M» с полосой. N = 3 (первые авторы) + реальное
число авторов с сервера (`GET functions/v1/community`; недоступна функция —
0, без ошибок) + 1 за каждого писателя устройства, который дошёл до цели, но
сервер его ещё не подтвердил; шаг — `next_model_every` с сервера, иначе
ru 20 / en 30; M = (⌊N/шаг⌋ + 1)·шаг. Та же формула, что в приложении
(`HandwritingCommunityStats.round`). Цель писателя — 150 русских / 200
английских слов (`prompted_word` своего языка). Дойдя до неё, писатель
«вступает»: отметка в `meta` `community:<writer_id>:<lang>`, выгрузка очереди,
затем `POST functions/v1/community {writer_id, language}` (нет POST — `GET`
без кеша), и один раз — окно «Ты в команде! Твой почерк — №N+1» со счётчиком
и полосой, которые двигаются (без анимации при `prefers-reduced-motion`).

## Формулы почерком

### Что это

Писатель один раз пишет пером все математические символы — цифры, латиницу,
греческие буквы, знаки действий и отношений, скобки, стрелки, знаки множеств
и логики, ∑ ∫ ∏, ℝ ℕ ℤ ℚ ℂ, пунктуацию и кириллицу. Потом он спрашивает у
ChatGPT решение задачи, дописав к вопросу наш промпт, вставляет ответ в
приложение — и получает тетрадную страницу, на которой формулы расставлены
**ровно так, как их сверстал бы LaTeX**, но каждый символ взят из его
собственных образцов, и каждый раз немного по-разному, чтобы ничего не
выглядело скопированным.

Символы — это обычные образцы: они пишутся в IndexedDB, уходят в ту же очередь
отправки и попадают в датасет, как слова (согласие 0.2, см. ниже).

### Как этим пользоваться

1. **Собрать символы.** В карточке писателя — «Символы». 288 символов в трёх
   раундах: 1 — основное для школьной и вузовской математики (79), 2 —
   расширенное (114), 3 — редкое (95). Каждый символ раунда 1 пишется трижды,
   раунда 2 — дважды, раунда 3 — один раз: 560 заданий, в перемешанном по
   писателю порядке, повторы разнесены. На листе — бледный образец символа
   (его x-высота ровно между пунктиром и строкой; выключается галочкой
   «Образец на листе»), над листом — символ, как его набирает KaTeX, его
   название, команда LaTeX и подсказка. Для решений достаточно первого раунда;
   чего не хватит, приложение попросит дописать само.
2. **Промпт.** «Решение почерком» → «Скопировать промпт для нейросети» (RU/EN),
   дописать его к своему вопросу в ChatGPT, Claude, DeepSeek или другой модели.
3. **Вставить** ответ нейросети целиком в поле «Вставьте ответ» (или «Вставить из
   буфера», где браузер это разрешает). Поле и все настройки сохраняются на
   устройстве для каждого писателя — перезагрузка ничего не теряет.
4. **Настроить** ползунками почерк и страницу; превью пересобирается само через
   четверть секунды после изменения. «Не хватает N символов: …» →
   «Дописать эти символы»: откроется лист только с этими символами, после
   последнего приложение вернётся к решению и пересоберёт его.
5. **Экспорт:** PNG и SVG текущей страницы, «Печать / PDF» (все страницы на
   листах A4, «Сохранить как PDF» в диалоге печати), «Штрихи JSON» — все
   штрихи всех страниц (`{schema: 'noto-render-0.1', writer_id, knobs, page,
   source_text, pages}`), чтобы их можно было, например, отдать плоттеру.

Промпт целиком (`CHATGPT_PROMPT_RU` в `js/solution.js`; есть и английский) —
он описывает ровно то подмножество Markdown и LaTeX, которое страница умеет
переписать от руки:

````text
Оформи ответ по этим правилам — его перепишут от руки в тетрадь, сохранив разметку:
— Markdown: заголовки #, ## и ###; **жирный**, *курсив*, ~~зачёркнутый~~; списки «- » и «1. »; вложенный пункт и всё, что относится к пункту (формула, пояснение), — с отступом 3 пробела; цитаты «> »; таблицы | a | b | со строкой |---|; разделитель ---; код в ```;
— формулы в строке пиши в $...$, отдельные формулы — в $$...$$ на отдельной строке;
— в LaTeX используй только: \frac \sqrt ^ _ \cdot \times \div \pm \le \ge \ne \approx \equiv \infty \int \sum \lim \to \Rightarrow \Leftrightarrow \in \notin \subset \cup \cap \varnothing \forall \exists \sin \cos \tg \ctg \log \ln \left( \right) \vec \overline \mathbb{R} \text{…}, греческие буквы, \begin{cases}, \begin{aligned} и \begin{pmatrix} (внутри $$);
— не используй \displaystyle, \boxed, \color, \tag, \label, \newcommand, \begin{align}, длинный \text{…}, \( \) и \[ \], HTML, ссылки, картинки и эмодзи;
— в ячейках таблицы — короткий текст и формулы в $...$, без $$ и переносов строк; не больше 5 столбцов;
— не больше двух уровней вложенности списков; короткие строки и абзацы, как в тетради;
— \cdot ставь только там, где его поставил бы ученик: 2x, а не 2\cdot x;
— последняя строка: «**Ответ:** …»;
— пиши на русском, если вопрос на русском;
— пиши так, как записал бы решение ученик, без замечаний об оформлении;
— если ответ длинный — не сокращай решение, но не добавляй лишних пояснений.
````

Забытый промпт ничего не ломает: разбор понимает и `\(…\)`/`\[…\]` из кнопки
«Копировать», HTML-теги `<b>`/`<i>`/`<sup>`, `x²` и `√2`, набранные юникодом;
ссылки превращаются в свой текст, картинки и эмодзи выбрасываются. Какие
LaTeX-команды выходят за поддерживаемый набор, видно в свёрнутом блоке
«Замечания к формулам».

### Как Markdown ложится на тетрадный лист

| Разметка | На листе |
| --- | --- |
| `# Заголовок` | по центру, крупнее (×1,4), подчёркнут |
| `## Заголовок` | по центру, крупнее (×1,2) |
| `### Заголовок` | у поля, подчёркнут |
| `####`… `######` | у поля, с сильным нажимом |
| `**жирный**` | сильнее нажим (перо ×1,55); формула внутри — тоже |
| `*курсив*`, `_курсив_` | сильнее наклон |
| `~~зачёркнутый~~` | зачёркнут от руки |
| `` `код` `` | написан как есть (похожий на формулу — формулой) |
| `- пункт`, `1. пункт`, `2) пункт` | висячий отступ: маркер (тире, номер) в слоте из двух клеток, текст и его переносы — по колонке текста |
| вложенный пункт, формула или абзац с отступом под пунктом | на колонке текста пункта; каждый уровень — ещё две клетки |
| `$$…$$` сразу под пунктом (даже без отступа) | принадлежит пункту: по центру его колонки |
| `- [ ]` / `- [x]` | нарисованный квадратик / с галочкой |
| `> цитата` | отступ и черта слева на всю высоту цитаты; `>>` — вторая черта |
| таблица `\| a \| b \|` + `\|---\|` | расчерчена от руки по клеткам: столбцы по ширине содержимого (на узкой странице сужаются, текст переносится внутри ячейки), линия под каждой строкой, выравнивание из строки `:--`/`:-:`/`--:`, шапка с нажимом; длинная таблица продолжается на следующей странице |
| ```` ```язык ```` … ```` ``` ```` | строки кода с отступами, в рамке по ширине самой длинной строки |
| `---`, `***`, `___` | линия через всю колонку текста |

Каждая строка ответа — своя строка в тетради; пустые строки дают одну пустую
строку, перед заголовком она есть всегда, перед отдельной формулой — никогда.
Вложенность определяется отступом: строка принадлежит пункту, если отступ хотя
бы на 2 пробела больше, чем у его маркера (чат-боты делают отступы в 2, 3 или 4
пробела — годится любой).

### Данные: образцы символов

Тот же `noto-0.1`, тот же объект, что у слова, с такими отличиями:

| Поле | Слово | Символ |
| --- | --- | --- |
| `sample_type` | `prompted_word` | `prompted_glyph` |
| `label` | слово | символ — ключ из `math_glyphs.json` (`α`, `≤`, `ℝ`, `−`…) |
| `prompt_id` | `ru_core_v1/<task_index>` или `en_core_v1/<task_index>` | `math_glyphs_v1/<id>`, например `math_glyphs_v1/greek.alpha` |
| `language` | `ru` или `en` | `math` |
| `is_dictionary_word` | `true` | `false` |
| `task_index` | строка ядра | индекс символа в `math_glyphs.json` |
| `word_group` | ярус | `math_glyph` |
| `order` | место в выдаче слов, с 1 | место в выдаче символов, с 1 |
| + | — | `glyph_id`, `latex` (`\alpha`), `glyph_category` (`greek_lower`…) |

Прогресс писателя: `progress.cursor` — русские слова (как было),
`progress.cursor_en` — английские, `progress.glyph_cursor` — символы, все
независимо. Черновики тоже раздельные: `draft:<id>` для русского слова (как
было), `draft:<id>:en` для английского, `draft:<id>:glyphs` для символа и `draft:<id>:glyphs:target` для
дописывания вне очереди (оно не трогает недописанный символ у курсора).
Черновик сохраняется только за тем писателем, чей лист открыт; уходя с экрана
письма, лист очищается.

**Дописывание вне очереди.** Символы, дописанные из «Решения почерком», не
двигают `glyph_cursor` и несут `glyph_targeted: true`. Их `order` — номер
ближайшего ещё не написанного вхождения этого символа впереди курсора (слот,
который образец заполнил); когда курсор до него доходит, лист его
перешагивает, так что одно и то же вхождение не просят дважды. Если все
вхождения уже позади, `order` = 0. Импорт такие образцы в курсор не считает.

**Согласие 0.2.** К тексту согласия добавлено: так же собираются рукописные
математические символы и буквы; они используются (а) для обучения и оценки
моделей почерка (датасет) и (б) локально на этом устройстве, чтобы писать
решения почерком писателя. Писатель с согласием 0.1 продолжает писать слова
как раньше, но перед первым символом видит обновлённое согласие ещё раз
(с пометкой, что изменилось) и после подтверждения попадает туда, куда шёл.
Версия уходит в конверте отправки (`consent_text_version`). Символы писателя
с согласием ниже 0.2 ждут в очереди (не теряются), пока он не согласится;
импорт файла с более новой версией согласия того же писателя поднимает её и
на этом устройстве. Сам вставленный текст решения на сервер датасета не
отправляется; только если в настройках указан URL модели почерка, слова между
формулами (с `writer_id` и seed) уходят на этот адрес — экран решения это
пишет.

### Как устроена раскладка

1. `solution.js` режет ответ на блоки: абзацы со строчными формулами и
   стилями, выключные формулы, заголовки, пункты списков (с глубиной
   вложенности), таблицы, код, цитаты (глубина `quote` у любого блока) и
   разделители.
2. `mathlayout.js` рендерит каждую формулу настоящим KaTeX в невидимый блок
   за пределами экрана и читает обратно геометрию: позицию, размер шрифта и
   точную рамку чернил каждого символа, черты дробей и надчёркивания, корни
   (знак + черта), растянутые скобки, акценты (`\vec`, `\hat`…). Единица —
   x-высота KaTeX (0,431 em).
3. `glyphs.js` сопоставляет каждому символу ключ (`normalizeKey`: `\cdot` →
   `⋅`, куски больших скобок → `(`, `\mathbb{R}` → `ℝ`, `\ne` → `≠`…) и
   находит экземпляры писателя, при нехватке — допустимую замену (`ϵ`↔`ε`,
   `−` → `-`, `…` → три точки, строчная ↔ заглавная у одинаковых по форме).
4. `compose.js` ставит на место каждого символа KaTeX один из экземпляров
   писателя (в его x-высотах, так что индексы уменьшаются ровно как в LaTeX),
   рисует черты от руки, растягивает скобки и корни по высоте, раскладывает
   строки по клеткам/линейке: базовая линия текста всегда на линии листа,
   высокая формула сдвигает строку на целые клетки, выключные — по центру
   своей колонки, перенос слов, новая страница. Колонка блока — поле плюс
   отступы его цитат и пунктов списка; линии таблиц, рамки кода и черты
   цитат рисуются от руки по решётке листа.
5. Текст между формулами (`textink.js`): модель почерка, если подключена →
   то же слово, написанное писателем при сборе слов → слово из его букв →
   системный шрифт с пометкой «не хватает».

Чего нет ни в одном источнике, рисуется шрифтом и попадает в «Не хватает …»;
«Показать недостающие» обводит такие места красным пунктиром.

### Ползунки: откуда берётся «небрежность»

Каждый ползунок — **множитель собственного разброса писателя**, измеренного
по его повторам одного и того же символа (`estimateProfile`: медианные,
устойчивые к выбросам оценки; пока повторов мало — разумные значения по
умолчанию, и экран об этом говорит). 0 — выключено, 1 — «как вы сами»,
2 — вдвое небрежнее.

| Ползунок | Что меняет |
| --- | --- |
| Общая небрежность | множитель для всех остальных сразу |
| Размер | разброс высоты символов |
| Наклон | разброс наклона от символа к символу |
| Строка | подскоки над строкой и под неё |
| Форма букв | плавное искажение формы (связное поле смещений — штрихи не рвутся) |
| Интервалы | неровность расстояний между буквами и словами |
| Дрейф строки | медленная волна вдоль строки: уходит вверх-вниз, чуть меняет размер и наклон |
| Нажим | разброс толщины линии |
| Смешивание вариантов | как часто символ — смесь двух написаний писателя с одинаковым числом штрихов |
| Как я ↔ как LaTeX | не множитель: слева — пропорции самого писателя, справа — каждый символ ровно в рамке KaTeX (по умолчанию 0,35) |
| Seed / 🎲 | номер «попытки»: тот же seed — та же страница штрих в штрих |

Случайность привязана к позиции символа, а не к порядку вызовов: сдвиг
«Наклона» меняет только наклон, не перетасовывая выбор экземпляров и форму.
Страница: бумага (клетка / линейка / чистый лист), чернила (синие, чёрные,
фиолетовые), размер почерка (x-высота в долях клетки, 0,42 по умолчанию),
поля (красная линия справа).

### Подключение модели почерка

Настройки → «Модель почерка (URL)». Когда модель подключена, **все слова
страницы пишет она**: текст между формулами, заголовки, пункты списков и их
маркеры («1.», «—»), ячейки таблиц, цитаты, строки кода. Формулы по-прежнему
собираются из символов писателя по раскладке KaTeX, а образцы слов и букв
писателя — только запасной путь, когда модель слово не знает или не ответила.
Для каждого слова приложение делает

```
POST <URL>
Content-Type: application/json

{ "writer_id": "…", "text": "уравнение", "seed": "1/word/3/model" }
```

и ждёт

```json
{ "strokes": [ [ [x, y, t, p], … ], … ], "width": 4.8 }
```

в единицах x-высоты писателя: Y вниз, 0 — базовая линия, −1 — линия
x-высоты, чернила начинаются около x = 0; `t` — мс, `p` — нажим 0..1 (можно
0). `width` можно опустить — возьмётся ширина чернил. `null` значит «не знаю
этого слова»: тогда оно берётся из слов и букв писателя. Ответ дольше 2,5 с,
ошибка сети или HTTP, пустые штрихи — то же самое, без сообщений, но это
считается ошибкой: после трёх ошибок подряд модель на этот рендер
отключается.
Слова блока (абзаца, пункта с маркером, всей таблицы, всего блока кода)
запрашиваются заранее и параллельно — до 6 запросов одновременно, так что
сервер должен выдерживать параллельные запросы; страница всё равно собирается
по порядку и не зависит от того, какой ответ пришёл первым.
Сколько слов пришло из модели и сколько раз она не ответила — в сводке под
превью. Запрос — межсайтовый `POST` с JSON, так что сервер должен отвечать
на CORS-предзапрос. Ответы кешируются по (текст, seed), и движение ползунков
не спрашивает модель заново.

Вместо URL скрипт на странице может определить функцию:

```js
window.NotoHandwritingModel = async (text, { seed, writer_id }) =>
  ({ strokes: [[[0, 0, 0, 0.5], [1, -1, 40, 0.5]]], width: 1 });  // или null
```

Она важнее URL.

### Тесты

Лежат вне деплоя, в `scripts/handwriting-tests/` (нужен Node 22):

```bash
node --test 'scripts/handwriting-tests/*.test.mjs'   # чистые модули: символы, вариации,
                                                     # разбор ответа, набор ↔ KaTeX
node scripts/handwriting-tests/mathlayout.e2e.mjs    # KaTeX-геометрия в Chromium (порт 8791)
node scripts/handwriting-tests/compose.e2e.mjs       # страницы целиком в Chromium (порт 8795)
```

Шаблон пути именно в кавычках: `node --test <каталог>` на Node 22 не
работает. e2e-проверки используют установленный Playwright и складывают
картинки в `scripts/handwriting-tests/out/` (в `.gitignore`). Юнит-тесты
гоняются в workflow перед каждой выкладкой.

### Ограничения

* Формула, которую KaTeX не смог разобрать, пишется как текст (и попадает в
  «Замечания»). Окружения — только `aligned`, `cases`, матрицы и соседние;
  `align` переписывается в `aligned`.
* Рукописного `\mathcal`/`\mathscr` нет: берётся обычная латинская буква.
  Жирный и прямой шрифт в формулах — тот же почерк.
* Черты дробей, надчёркивания и черта корня рисуются процедурно (рукой, но не
  из образцов); знак корня — из образца «√» (только галочка).
* Разброс почерка честный только после повторов: пока каждый символ написан
  один раз, «как вы сами» — это значения по умолчанию.
* Экран «Решение почерком» считает всё в основном потоке: на длинном решении
  со старым планшетом перерисовка может занимать секунду.
* Печать в PDF зависит от браузера: на iPad «Сохранить как PDF» — через
  «Поделиться» в диалоге печати.

## Ограничения, о которых стоит знать

* **Приватный режим Safari** — IndexedDB там урезан; собирать в нём не стоит.
* **Палм-реджект:** как только на листе писали пером, касания пальцем
  игнорируются (об этом появляется подсказка). До первого касания пером писать
  пальцем можно.
* **Поворот планшета посреди слова** ничего не портит: записанные координаты
  остаются в системе координат первой точки (`canvas_w`/`canvas_h`), а лист
  подгоняет их под новый размер только при отрисовке — подобием, одним
  масштабом без растяжения, так что форма написанного не меняется. Ровно как
  на iOS.
* **Нажим у пальца** браузер сообщает как 0.5 — это не сила касания, а значение
  по умолчанию из спецификации.

## Обновление сайта

Файлы оболочки кешируются Service Worker'ом. После деплоя поднимите `CACHE`
в `sw.js` (сейчас `noto-collect-v3`), иначе у уже открывавших сайт останется
старая версия до сброса кеша. Новый файл приложения — добавьте его в `SHELL`
в `sw.js` и в список проверки в `.github/workflows/handwriting-pages.yml`
(workflow сам проверяет, что всё из `SHELL` существует).
